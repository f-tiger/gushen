# 2026-09-28 方法修复与三轮 Prompt

用户要求将实际股票子仓纳入“调研清楚、用好方法论、辅助 AI 时代赚钱”的任务。

三轮：①定位生产分支与真实浏览器计算链；②以时点、持仓漂移、月初休市、成本和基准反查旧回测；③修复后以独立手算验证，并展示用户能下载的证据，不把程序运行或回测表现称为盈利。

新增 `walk-forward-close-v2`：前日数据形成权重，月内首个可用交易日收盘执行；旧仓先承受当日涨跌；两次调仓间权重随价格漂移；初始建仓费用计入原始本金。算法失败直接报错，不悄悄回退另一种策略。每笔成本定义为调仓前 NAV × 股票权重绝对变动合计 × 基点，不计税费、额外滑点和期末清仓。

目标测算增加相同窗口与成本的等权基准、回撤及 JSON 换仓账本。对数正态情景用历史算术均值与波动，明示参数不变假设，不能称为经校准的未来成功概率。组合推荐的历史指标是样本内拟合。

40 项本地测试通过：保留 30 个不受影响的 Python 对照；10 个新增测试手算首次成本、当日成交顺序、自然漂移、周末跨月调仓、未来数据隔离及输入边界。旧 backtest/goal fixture 保留作历史资料，其错误口径不再作为新实现正确性的验收标准。TypeScript 与 Vite 构建通过。

仍有限制：当前标的池选择与幸存者偏差，报价权限与完整性，未计税费/额外滑点，未知未来分布。本次没有实盘投资、付费订单或未来收益证据，也没有重构未上线的 Python 后端。

依据：SEC 13F FAQ https://www.sec.gov/rules-regulations/staff-guidance/division-investment-management-frequently-asked-questions/frequently-asked-questions-about-form-13f ；Bailey 等回测过拟合研究 https://www.davidhbailey.com/dhbpapers/backtest-prob.pdf 。这些来源支持研究纪律，不验证本产品收益。

补充修复：HRP、逆波动、动量原先忽略风险画像的仓位上限；现在所有方法都会执行最终权重约束，不可行时明确报错。历史 Python 的忽略上限行为不再作为验收目标；独立测试验证两标的各上限 50% 时必须各占 50%，各上限 20% 时必须报错。
