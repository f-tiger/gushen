# 股神（Gushen）—— 美股投资模拟平台 · 架构设计文档

> 版本：v0.1（初稿）
> 定位：美股投资**模拟交易** + 数据/AI 辅助的**投资指导**平台

---

## 1. 项目定位

| 层 | 说明 | 价值 |
|----|------|------|
| **模拟交易层** | 虚拟资金买卖美股，撮合、持仓、盈亏、排行榜 | 零风险练手、教学、策略验证 |
| **数据/AI 指导层** | 行情+新闻+财报 → AI 分析 → 选股/择时/组合诊断 | 为真实投资提供参考信息 |

设计原则：**模拟先行，指导为辅**。先把「查行情 → 模拟下单 → 看持仓盈亏」这条主链路跑通，再逐步叠加 AI 能力。

### 1.1 合规红线（重要）

本平台提供的是**信息与教育服务**，不是持牌投资顾问：

- 所有 AI 输出必须带免责声明：「仅供参考，不构成投资建议」。
- 不承诺收益、不代客理财、不接触真实资金交易通道。
- 用户真实投资决策与后果由用户自负。
- 新闻/研报等第三方数据需遵守其许可协议，注意版权与再分发限制。

## 2. 技术栈选型（推荐）

选型围绕两个事实：**（a）数据与量化/AI 是核心**，Python 生态最顺；**（b）前端要有专业的 K 线交互体验**。

| 层 | 选型 | 理由 |
|----|------|------|
| 后端 API | **Python + FastAPI** | 异步高性能，天然贴合数据/AI/量化生态 |
| 数据处理 | **pandas / numpy / pandas-ta** | 行情清洗、技术指标计算 |
| 回测引擎 | **vectorbt / backtrader** | 向量化回测，快速验证策略 |
| 主数据库 | **PostgreSQL** | 事务强一致；用扩展一库多能（见下） |
| 时序扩展 | **TimescaleDB**（PG 扩展） | K 线/tick 按时间分片、连续聚合 |
| 向量扩展 | **pgvector**（PG 扩展） | 新闻/财报语义检索做 RAG，起步不必单独上向量库 |
| 缓存/实时 | **Redis** | 实时行情缓存、排行榜、限流、任务队列 |
| 定时任务 | **Celery / APScheduler** | 周期性拉行情、算信号、跑回测 |
| AI | **Claude API（Opus/Sonnet）** | 投研问答、组合诊断、策略生成 |
| 前端 | **React + TypeScript + Vite** | 生态成熟，组件化 |
| 图表 | **TradingView Lightweight Charts** | 免费、专业 K 线交互 |
| 部署 | **Docker Compose 起步** | 一键起本地全套依赖，后续可迁 K8s |

> 核心取舍：**起步阶段用「一个 PostgreSQL + 两个扩展（Timescale + pgvector）」覆盖关系型、时序、向量三类需求**，把运维复杂度压到最低；等规模上来再拆分（如时序迁 ClickHouse、向量迁专用库）。

```
┌─────────────────────────────────────────────────────────┐

│   行情/K线   模拟交易   持仓组合   AI 助手   回测   排行榜   │
└───────────────────────────┬─────────────────────────────┘
                            │ REST / WebSocket
┌───────────────────────────┴─────────────────────────────┐
│                    后端 API (FastAPI)                     │
│  ┌────────┐ ┌────────┐ ┌────────┐ ┌────────┐ ┌────────┐ │
│  │行情服务│ │交易引擎│ │账户组合│ │AI 分析 │ │回测引擎│ │
│  └───┬────┘ └───┬────┘ └───┬────┘ └───┬────┘ └───┬────┘ │
└──────┼──────────┼──────────┼──────────┼──────────┼──────┘
       │          │          │          │          │
┌──────┴──────────┴──────────┴──────────┴──────────┴──────┐
│  PostgreSQL (Timescale + pgvector)   Redis   外部数据源   │
└──────────────────────────────────────────────────────────┘
```

### 3.1 关键数据流

**行情更新**：定时任务 → 拉外部 API → 写 `market_bars`（Timescale）→ 更新 Redis 缓存 → WebSocket 推前端。

**模拟下单**：前端下单 → 交易引擎校验（资金/标的/市场时段）→ 按最新价撮合 → 写 `orders`/`transactions` → 更新 `positions` 与现金 → 返回。

**AI 问答**：用户提问 → 检索相关行情/新闻（pgvector）→ 组装上下文 → Claude → 带免责声明返回，并落库 `ai_conversations`。

## 4. 存储方向（详细）

按数据形态划分职责：

### 4.1 关系型（PostgreSQL）—— 强一致、事务

核心表（字段为示意）：

```
users              (id, email, hashed_password, created_at)
portfolios         (id, user_id, name, cash_balance, base_currency)
instruments        (symbol, name, exchange, sector, currency, is_active)
positions          (id, portfolio_id, symbol, quantity, avg_cost)
orders             (id, portfolio_id, symbol, side, type, qty, price,
                    status, created_at, filled_at)   -- side: buy/sell; type: market/limit
transactions       (id, portfolio_id, order_id, symbol, side, qty,
                    price, fee, cash_delta, created_at)
watchlists         (id, user_id, name)
watchlist_items    (watchlist_id, symbol)
```

要点：
- **资金/持仓变更走数据库事务**，保证下单不会出现「扣了钱没加仓」。
- `positions` 用「数量 + 平均成本」，卖出时算已实现盈亏；未实现盈亏由最新价实时计算，不落库。
- 交易全流水存 `transactions`，可回溯、可对账。

### 4.2 时序（TimescaleDB hypertable）—— 行情

```
market_bars (time, symbol, timeframe, open, high, low, close, volume)
   → hypertable，按 time 分片
   → 连续聚合 (continuous aggregate) 自动生成 日线/周线
quotes      (time, symbol, price, bid, ask)   -- 实时/近实时报价（可选）
```

要点：写多、按时间范围与聚合查询多；用 Timescale 的压缩策略控制存储成本。

### 4.3 向量（pgvector）—— AI 检索

```
documents   (id, symbol, type, title, url, published_at, content)
              -- type: news / filing / research
embeddings  (document_id, chunk_id, vector, chunk_text)
```

要点：新闻/财报切块 → 向量化 → 供 AI 问答做 RAG。

### 4.4 缓存（Redis）

- 最新报价（`quote:{symbol}`），减轻数据库压力
- 排行榜（收益率 sorted set）
- 外部 API 限流计数、任务队列 broker

## 5. 行情数据源方案（免费/低成本起步）

采用「**免费源起步 + 抽象适配层**」策略，避免被单一供应商锁死。

| 数据源 | 类型 | 免费额度 | 用途 |
|--------|------|----------|------|
| **yfinance**（Yahoo） | 历史/延迟行情 | 无官方 key，非官方接口 | 历史 K 线、快速起步 |
| **Finnhub** | 准实时行情/新闻 | 60 次/分钟 | 报价、公司新闻 |
| **Alpha Vantage** | 行情/基本面 | 25 次/天（较紧） | 补充基本面 |
| **Polygon.io** | 行情 | 免费档有限速 | 后续可升级实时 |

**抽象设计**：定义统一 `MarketDataProvider` 接口（`get_bars()`, `get_quote()`, `get_news()`），各数据源做适配器实现。业务层只依赖接口，换源/多源聚合只改配置。

**降级与缓存**：优先读 Redis/DB 缓存 → 未命中再打外部 API → 触发限流则退避重试或切备用源。行情标注「延迟数据」以符合免费源特性。

## 6. AI 方向（详细）

分四个能力，从易到难落地：

### 6.1 投研问答助手（优先）
- 基于 Claude，接入行情 + 新闻做 **RAG**。
- 场景：「AAPL 最近财报怎么样」「解释一下这只票为什么跌」。
- 每条回答强制附免责声明。

### 6.2 组合诊断
- 输入用户持仓 → 分析集中度、行业分布、风险敞口 → 给再平衡提示。
- 结合量化指标（波动率、相关性）+ Claude 的自然语言解读。

### 6.3 选股/信号
- 因子打分：动量、估值、财报质量等 → 排序生成候选池。
- 结果落 `ai_signals` 表，前端展示并标注仅供参考。

### 6.4 策略回测助手（进阶）
- 用户用自然语言描述策略 → Claude 生成可执行回测代码 → vectorbt 跑历史 → 返回收益/回撤/夏普。
- 代码执行需**沙箱隔离**，防止任意代码风险。

### AI 工程注意
- **Prompt 与上下文分层**：系统提示固定合规声明；检索到的数据作为上下文注入。
- **成本控制**：缓存常见问答；长上下文用 prompt caching。
- **可追溯**：AI 输出与所依据的数据来源一并记录，便于复盘。

| 阶段 | 目标 | 交付 |

| **P0 地基** | 项目脚手架、DB、鉴权、Docker Compose | 能起服务、能登录 |

## 9. 风险与注意事项

- **合规**：全程「信息/教育」定位，AI 输出必带免责声明，不碰真实资金交易。
- **数据许可**：免费源多为个人/非商用，商用前需核实条款、必要时升级付费。
- **免费源限速与稳定性**：靠适配层 + 缓存 + 多源降级兜底。
- **AI 幻觉**：金融场景零容忍编造数据；数字类回答须来自检索到的真实数据，并标注来源。
- **代码执行安全**：回测助手生成的代码必须沙箱隔离。
- **成本**：AI 与实时行情是主要开销，用缓存与分级策略控制。
